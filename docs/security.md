# Gatherly AI — Security Specification & Threat Model

## 1. Application Threat Model

Gatherly AI provides constraint-aware event planning assistance with local and demo AI integration. The threat model is focused on realistic client-side and inference attack vectors:

| Threat Category | Potential Vector | Mitigation & Enforcement | Status |
|---|---|---|---|
| **Arbitrary Code / HTML Injection** | Malicious AI output or user input containing `<script>` or XSS tags | React JSX native escaping; zero usage of `dangerouslySetInnerHTML`. Zod string schemas strictly sanitize and bound text length. | ✅ Verified |
| **Model Output Poisoning** | Malicious or malformed JSON generated by LLM | Strict runtime Zod schema parsing (`AIGeneratedPlanOutputSchema`, `AIPlanRevisionProposalSchema`). Malformed structures are rejected prior to state entry. | ✅ Verified |
| **Denial of Service (Inference Exhaustion)** | Unbounded prompts or concurrent inference flooding | Local timeout of 45,000ms enforced with `AbortController`. Backend proxy applies sliding-window rate limiting (30 requests/minute/IP) and bounded payload limits (50 KB). | ✅ Verified |
| **Floating-Point Financial Inaccuracies** | Rounding exploits or fractional penny drift | All financial arithmetic is exclusively calculated in integer minor units (paise: 1 INR = 100 paise). Floating-point arithmetic is forbidden in the domain layer. | ✅ Verified |
| **Unintended Data Loss / Silent Overwrites** | AI hallucinating changes or silently erasing confirmed user records | Domain constraint engine enforces that AI revisions require explicit user review and approval. Confirmed actual costs and completed tasks are immutable to AI proposals. | ✅ Verified |
| **Corrupt Storage Injection** | Malicious or malformed local storage manipulation | `LocalStorageAdapter` uses schema-versioned migrations with Zod validation. Parsing errors are caught gracefully, falling back to clean state without app crashes. | ✅ Verified |
| **Secret Leakage** | Leaking private API keys or personal credentials in bundles or commits | Zero secrets required or bundled. Local Ollama and Demo providers operate without external API keys. `.env.example` contains only placeholder references. | ✅ Verified |

## 2. Input & Output Validation Boundaries

1. **User Input Validation**:
   - Dates validated using ISO 8601 regex (`^\d{4}-\d{2}-\d{2}$`).
   - Guest count bounded between 1 and 50,000.
   - Budgets bounded between 0 and 100 Crore INR.
   - Text fields bounded to prevent memory exhaustion attacks.

2. **AI Provider Output Boundary**:
   - Every inference response passes through Zod runtime parsers.
   - If an LLM returns missing fields, negative costs, or invalid categories, `safeParse` fails safely and surfaces a polite fallback error to the user without contaminating persistent storage.

---

## 3. Server-Side Security (FastAPI Proxy)

When deploying the optional remote inference service (`backend/main.py`):
- **CORS**: Restricted strictly to authorized origins defined in `ALLOWED_ORIGINS`.
- **Payload Bounds**: Max string lengths and array limits enforced via Pydantic `Field(max_length=...)`.
- **Rate Limiting**: Sliding window tracking by client IP returning `429 Too Many Requests`.
- **Private Network Isolation**: The Ollama endpoint is kept on internal localhost (`http://localhost:11434`) and is never exposed to the public internet.
